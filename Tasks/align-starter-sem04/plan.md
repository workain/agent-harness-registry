# plan.md — согласование шаблона `coding-agent-starter` и демо-репозитория с Семинаром 4

## Цели

1. **Шаблон** `templates/coding-agent-starter/` — без противоречий Семинару 4 и без
   самопротиворечий. Через ветку и PR, со независимым ROAST.

   настоящей историей: кейсы, которые семинар называет сыгранными, сыграны по-настоящему.
   Это главный деливебл.
3. **`Tasks/seminar-findings.md`** — один сводный самостоятельный список находок по Семинару 4
   для автора его ветки. Ветку семинара не править.
4. **Семинар 5** — поверхностный проход по `_research/coding-agent/10-template-work-order*.md`.

## Рамка, по которой принимались решения

Критерий — **«не противоречит семинару»**, а не «совпадает с ним». Шаблон — продукт, он
вправе содержать больше, чем покрывает занятие. Отсюда классификация:

- **A** — противоречие семинару. Чинить обязательно.
- **B** — шаблон противоречит сам себе. Чинить, это дефект качества.
- **C** — шаблона просто больше, чем семинара. НЕ выпиливать; чинить формулировку, если
  шаблон подаёт как общее правило то, чему семинар учит обратное.

Рекомендация предыдущей ревью выпилить ворота и `doc/adr/` из дня 0 по этой рамке отклонена:
её факты верны, вывод — нет.

**Результат.** Шаблон перестал противоречить сам себе, а демо-репозиторий перестал быть
описанием: каждое состояние, которое слайд называет настоящим, теперь существует в коммите с
прогоном за ним.

**Главный риск.** Я дважды приняла за доказательство то, что им не было: вызов хука напрямую
вместо настоящего отказа в сессии, и «проверила, что команда из README работает» без проверки,
в каком состоянии она оставляет репозиторий. Оба раза поймал независимый ROAST, не я.

**Главный открытый вопрос.** Сквозной календарь занятия (день 0 → месяц 1 → месяц 4) со
настоящими датами git не сводится и сводиться не должен; сейчас `visual.backup` s35 пытается
это сделать и ошибается в обеих датах. Решение — за автором ветки семинара.
