# CLAUDE.md

`signup-landing` — одна статическая страница с формой заявки на демо-урок (имя + email), без
своего бэкенда: заявка уходит на внешний сервис приёма форм. «Готово» = страница собирается,
форма не отправляет пустые и неверные поля, тесты зелёные.

## Safety / scope boundaries

- Никогда не запускать деплой на прод без явного запроса.

## Build, test, verify

- Build: `npm run build`
- Test: `npx playwright test`
- Run locally: `npm run dev`
- To verify a change actually works (not just compiles): открыть `dist/index.html` после
  сборки, вручную отправить форму с заполненными и с пустыми полями.

Один раз после клонирования, **до** первого `npx playwright test`:

- `npm ci` — поставить зависимости.
- `npx playwright install chromium` — скачать браузер. Одна загрузка на машину, не на проект,
  ~650 МиБ в `~/.cache/ms-playwright/`. Без неё падают сразу все 4 теста, за миллисекунды и не
  по делу: `browserType.launch: Executable doesn't exist at .../chrome-headless-shell`.

## Project-specific conventions

- Что считается валидным, объявлено в `index.html` атрибутами `required` / `pattern` /
  `type="email"`. `src/validate.js` читает те же атрибуты через Constraint Validation API и
  рисует сообщения в странице. Новое правило валидации — в разметку, не второй копией в JS.
- `novalidate` на форме стоит намеренно: он отключает браузерные пузыри, а не проверки.
- Тесты не ходят в интернет: запрос к сервису приёма форм перехватывается `page.route`
  в `tests/form.spec.ts`. Новый тест, отправляющий форму, обязан делать то же.
- `action` формы в `index.html` — заглушка `REPLACE_WITH_YOUR_FORM_ID`. Свой endpoint
  подставляется перед деплоем; в репозиторий он не коммитится.

## Repository etiquette

- Ветка `issue-NNN-краткое-описание`, создаётся до первой правки; прямо в `main` не пушим —
  ветка и PR, даже на одну строку.
- Коммитить часто, после каждого осмысленного шага: падение процесса не должно терять работу.
- Задачи — GitHub Issues этого же репозитория. Закрывать со ссылкой на то, что реально попало
  в репозиторий (SHA коммита, номер влитого PR), а не со словами «готово».

## Where things live (pointers, not inline content)

- Решения: `DECISIONS.md` — append-only журнал **почему**, а не что; в этот файл датированные
  обоснования не переносятся.
- Ворота: `.claude/settings.json` — два `PreToolUse`-хука (коммит в `main`/`master`; `rm -rf`,
  цель которого раскрывает шелл), и `.claude/hooks/selftest-branch-guard.sh`, который проверяет,
  что оба действительно срабатывают. Правка `settings.json` — перезапуск самотеста; он же
  печатает, где эти ворота не закрываются.
- Деплой: `.claude/skills/deploy/SKILL.md` — вся процедура публикации на прод, от предполётной
  проверки до сверки с продакшен-URL. Её здесь нет намеренно: она нужна не каждой сессии, а
  `disable-model-invocation: true` в её фронтматтере — это та самая граница «не деплоить без
  явного запроса», сделанная механикой вместо просьбы. Запускается только явным `/deploy`.
- MCP: `.mcp.json` — **пример без ключей, не подключение**. Токен в нём не лежит и не будет:
  вместо значения — `${GITHUB_PERSONAL_ACCESS_TOKEN}`, переменная окружения. Переменная не
  задана, поэтому `claude mcp list` показывает `Pending approval` и называет её как
  недостающую. Так и задумано — почему, разобрано в «Ступень 5» README сборки; решение
  подключать ли сервер по-настоящему остаётся за владельцем.
- Ревью: `.claude/agents/diff-reviewer.md` — субагент, ревьюящий diff перед мержем. В его
  `tools` нет `Write`/`Edit`: он не обещает не чинить найденное, а не может — находка
  остаётся находкой, а не тихой правкой мимо ревью.

## Cross-engine interop

`AGENTS.md` — символическая ссылка на этот файл, не копия: один канонический текст читают и
Claude Code, и движки, которые ищут `AGENTS.md`. Копировать каталог проекта — только
`cp -RP`: без `-P` симлинк превратится в отдельный файл, и две копии начнут разъезжаться.

## Operating budgets

Два числа, которые больше никто не назовёт.

- **Контекст: потолок 100k токенов** (`--autocompact 100000`). Максимум движка — это предел, а
  не цель: сессия, идущая у предела, перечитывает весь контекст каждый ход, и счёт растёт от
  размера контекста, а не от сделанной работы.
- **Инструкции: потолок 800 слов** в этом файле. Всё, что здесь написано, грузится каждый ход и
  облагает налогом каждый запрос. Если новое правило пробивает потолок, что-то другое
  сокращается или уезжает из этого файла — а не дописывается сверху.

## Maintenance discipline

Такой файл растёт только добавлением, если его никто не сокращает. Добавляя раздел, спроси,
какой существующий должен сжаться или уйти. Датированное обоснование прошлого решения — не
сюда: здесь только действующее правило.

Правило, записанное как обязательное, но ничем механически не проверяемое, тихо разлагается:
либо проверка появляется вместе с правилом, либо правило честно помечено как совет.
