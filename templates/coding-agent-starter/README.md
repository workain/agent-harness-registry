# Шаблон простого репозитория для кодинг-агента

Заготовка проекта, в котором работает кодинг-агент (Claude Code и совместимые).
Семнадцать файлов (считая симлинк `AGENTS.md`), ни одного лишнего: каждый отвечает
на один вопрос, который иначе агент решит за вас сам.

Это **простой** шаблон — стартовый. Есть и полный, со скиллами, субагентами, MCP,
профилями и рендерером вариантов: `templates/base-project-template/` в
`workain/agent-harness-registry`. Начинать лучше отсюда.

## Начать

Шаблон живёт в `templates/coding-agent-starter/` репозитория
[`workain/agent-harness-registry`](https://github.com/workain/agent-harness-registry) —
это его единственный дом. Скопировать каталог себе:

```
git clone https://github.com/workain/agent-harness-registry.git
cp -RP agent-harness-registry/templates/coding-agent-starter мой-проект
cd мой-проект                                  # -P обязателен, см. ниже
rm -rf .git && git init -b main
bash .claude/hooks/selftest-branch-guard.sh    # убедиться, что ворота живые
```

`AGENTS.md` — **симлинк** на `CLAUDE.md`, не копия: один канонический текст читают и
Claude Code, и движки, которые ищут `AGENTS.md`. Копировать только `cp -RP`; без `-P`
симлинк превратится в отдельный файл, и две копии начнут тихо разъезжаться.

Дальше — три файла, по порядку, до первой строки кода:

1. `spec.md` — что делаем и что значит «готово».
2. `CLAUDE.md` — строка идентичности и **одно** правило-ворота.
3. `DECISIONS.md` — не трогать. Он заведён пустым намеренно.

## Что внутри

| Файл | Отвечает на вопрос |
|---|---|
| `CLAUDE.md` | Что агенту нельзя делать самому и куда смотреть за остальным |
| `AGENTS.md` | То же самое для движков, которые ищут `AGENTS.md` (симлинк, не копия) |
| `spec.md` | Что считается «готово» — до того, как написан код |
| `DECISIONS.md` | Почему было принято решение, которого уже не помнит никто |
| `doc/adr/` | То же для решений, которые переживут своих авторов |
| `.tasks/` | Что уже проверено в текущей задаче и что осталось |
| `.claude/settings.json` | Ворота: коммит прямо в `main` отклоняется |
| `.claude/hooks/selftest-branch-guard.sh` | Доказательство, что ворота правда срабатывают |
| `tests/CLAUDE.md` | Правила, которые действуют только на тесты |
| `doc/claude-md-sections.md` | Заготовки разделов `CLAUDE.md` — на потом, не на сейчас |

## Три принципа, на которых он держится

### 1. День 0: ворота есть, остальное пусто

`CLAUDE.md` в этом шаблоне почти пуст, и это не недоделка. Всё, что в нём написано,
грузится каждый ход и облагает налогом каждый запрос. Правило, написанное впрок,
нечем проверить — и оно тихо разлагается, пока кто-нибудь не обнаружит, что агент
его давно игнорирует, а файл всё ещё утверждает обратное.

Поэтому день 0 — это идентичность проекта и **одно** правило: то, цена нарушения
которого для вас реальна. Остальные разделы заведены заготовками в
`doc/claude-md-sections.md` и вносятся тогда, когда появился конкретный повод.

### 2. Правило трёх адресов

У знания о проекте есть три места, и корневой `CLAUDE.md` — только одно из них.
Класть всё в него — самая частая и самая дорогая ошибка: файл разрастается,
его начинают читать по диагонали, и правило перестаёт работать ровно тогда,
когда правил становится много.

| Адрес | Что туда | Почему именно туда |
|---|---|---|
| **Комментарий в коде** | Неочевидное ограничение конкретной строки | Читается ровно тем, кто правит эту строку, и не может от неё отстать |
| **Файл рядом с кодом** (`tests/CLAUDE.md`) | Правило, действующее на один каталог | Не грузится тем, кто в этот каталог не заходит |
| **Корневой `CLAUDE.md`** | Общепроектное — и **указатели** на первые два | Указатель стоит одну строку, содержание — каждый запрос |

Корневой файл после разноса должен стать **короче**, а не длиннее. Если он вырос —
разноса не было, было копирование.

> **Честно о механике.** Подхватывает ли ваш движок `tests/CLAUDE.md` сам, по пути
> правки, — зависит от движка и версии; проверьте на своём. Поэтому корневой
> `CLAUDE.md` тут **называет** этот файл в разделе «Где что лежит»: так правило находится
> в любом случае, а авто-подхват, если он есть, просто экономит ход.

### 3. Правило без проверки — это совет

Ворота в `.claude/settings.json` идут вместе с `selftest-branch-guard.sh`, который
запускает их на десятке сценариев и печатает результат. Он же печатает **пять
случаев, где эти ворота молчат** — `git -C`, `/usr/bin/git`, `env git`, вторая строка
многострочной команды, ветка по умолчанию не `main`/`master`.

Это сделано намеренно. Ворота, про которые не сказано, где они не работают, опаснее
отсутствующих: на них полагаются. Запускайте самотест после каждой правки
`settings.json` и после обновления агента.

## Чего здесь нет

Скиллов, субагентов, MCP, CI, профилей. Не потому что это неважно —
потому что на день 0 неважно. Когда понадобится: `base-project-template`
в том же `agent-harness-registry` (ссылка выше).
