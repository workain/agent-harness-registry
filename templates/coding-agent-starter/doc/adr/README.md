# doc/adr — архитектурные решения

**Эта папка — «по поводу», а не день 0.** Шаблон везёт её заранее, чтобы формат не пришлось
выдумывать в момент, когда решение уже надо записать, — но включать её надо по сигналу.
Сигнал простой и он же порог: запись не влезает в три строки `DECISIONS.md`. Пока все ваши
решения влезают — `DECISIONS.md` достаточно, а эту папку можно удалить целиком, ничего не
потеряв: `0001` ниже фиксирует решение вести ADR, и если вы его не приняли, оно неверно.

Формат — Nygard / `adr-tools`: один файл на решение, имя `NNNN-краткое-название.md`,
нумерация сквозная и не переиспользуется.

Отличие от `DECISIONS.md`: там короткая строка «почему» по любому решению, здесь —
решения с последствиями, которые переживут своих авторов и на которые будут ссылаться.

**Статус меняется, текст — нет.** Отменённое решение не редактируется и не удаляется:
у него ставится `Status: Superseded by ADR-NNNN`, а новое решение пишется отдельным
файлом. История того, что вы когда-то считали правильным, — и есть ценность этой папки.

Новый ADR — копия `0000-template.md` со следующим номером.

**Честно о силе доказательства.** ADR — задокументированная с 2011 года и широко применяемая
практика **для людей**. Контролируемого измерения «ADR помогают кодинг-агенту» нет ни одного.
Здесь это здравый перенос, а не вывод из данных.
