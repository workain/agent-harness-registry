# Разделы CLAUDE.md — заготовки

Не копировать все сразу. Каждый раздел вносится тогда, когда появился повод —
конкретный случай, когда агент не угадал и это стоило времени.

---

## Build, test, verify

Повод: агент запустил не ту команду или «проверил» сборкой то, что сборкой не проверяется.

```markdown
## Build, test, verify

- Build: `<команда>`
- Test: `<команда>`
- Lint: `<команда>`
- Run locally: `<команда>`
- Проверить, что правка ПРАВДА работает (а не просто собирается): `<команда / шаги руками>`
```

Последняя строка — самая ценная и чаще всего забытая. «Собирается» и «работает» —
разные утверждения; агент по умолчанию докажет первое и отчитается за второе.

Сюда же — разовые шаги после клонирования (скачать браузер, поднять БД, поставить
зависимости), если без них тесты падают мгновенно и не по делу.

## Repository etiquette

Повод: в репозитории появился второй участник — человек или сессия.

```markdown
## Repository etiquette

- Ветка `<схема имени>`, создаётся до первой правки. Прямо в `main` не коммитим.
- Коммитить часто: падение процесса не должно терять работу.
- Задачи — <где они лежат>. Закрывать ссылкой на то, что реально попало в репозиторий
  (SHA, номер влитого PR), а не словами «готово».
```

## Где что лежит (указатели, не содержание)

Повод: файл начал толстеть. Это и есть третий адрес из «правила трёх адресов» (README).

```markdown
## Где что лежит

- Решения: `DECISIONS.md` — журнал «почему». Датированные обоснования — туда, не сюда.
- Архитектурные решения: `doc/adr/` — по одному файлу на решение.
- Ворота: `.claude/settings.json` + `.claude/hooks/selftest-branch-guard.sh`.
- Правила тестов: `tests/CLAUDE.md` — читать перед правкой в `tests/`.
- Текущая задача: `.tasks/active/` — один файл на задачу.
```

Здесь только адрес и одна строка «что там». Как только сюда переехало содержание —
раздел перестал быть указателем.

## Потолок

Повод: файл перевалил за то, что вы готовы платить каждым запросом.

```markdown
## Потолок

- **Инструкции: <N> слов** в этом файле. Новое правило, пробивающее потолок, означает,
  что что-то другое сокращается или уезжает в свой адрес — а не дописывается сверху.
```

Такой файл растёт только добавлением, если его никто не сокращает. Добавляя раздел,
спросите, какой существующий должен сжаться или уйти.
