# Заготовки — вносится, когда появится повод

Здесь лежит то, что шаблон УМЕЕТ, но на день 0 не заводит: разделы `CLAUDE.md`, правило с
шаблоном путей и первая запись в `doc/adr/`. Не копировать всё сразу. Каждый блок вносится
тогда, когда появился повод: конкретный случай, когда агент не угадал и это стоило времени.

Почему они здесь, а не сразу в проекте: содержимое `CLAUDE.md` грузится каждый ход и
облагает налогом каждый запрос, а правило, написанное впрок, нечем проверить — оно тихо
разлагается, пока кто-нибудь не обнаружит, что агент его давно игнорирует, а файл всё ещё
утверждает обратное. Заготовка ничего не утверждает: она ждёт повода.

---

## Build, test, verify

Повод: агент запустил не ту команду или «проверил» сборкой то, что сборкой не проверяется.

```markdown
## Build, test, verify

- Build: `<команда>`
- Test: `<команда>`
- Lint: `<команда>`
- Run locally: `<команда>`
- Проверить, что правка ПРАВДА работает (а не просто собирается): `<команда / шаги руками>`
```

Последняя строка — самая ценная и чаще всего забытая. «Собирается» и «работает» —
разные утверждения; агент по умолчанию докажет первое и отчитается за второе.

Сюда же — разовые шаги после клонирования (скачать браузер, поднять БД, поставить
зависимости), если без них тесты падают мгновенно и не по делу.

---

## Repository etiquette

Повод: в репозитории появился второй участник — человек или сессия. **Кроме третьего пункта:**
он про острый край хука, который шаблон везёт живым, поэтому нужен с первой сессии, а не по
поводу. Если вносите только его — вносите его одного.

```markdown
## Repository etiquette

- Ветка `<схема имени>`, создаётся до первой правки. Прямо в `main` не коммитим.
- Коммитить часто: падение процесса не должно терять работу.
- `git switch … && git commit …` одной командой хук отклонит: он читает ветку до запуска
  всей строки. Переключение ветки — отдельной командой.
- Задачи — <где они лежат>. Закрывать ссылкой на то, что реально попало в репозиторий
  (SHA, номер влитого PR), а не словами «готово».
```

Третья строка — не абстрактная вежливость, а острый край того самого хука, который шаблон
везёт живым: он описан в `$comment` внутри `.claude/settings.json` и воспроизводится
самотестом (строка `chained 'git switch … && git commit'`). Поэтому она и не ждёт второго
участника: наступить на неё можно в одиночку, в первой же сессии.

## Правило с шаблоном путей — `.claude/rules/<имя>.md`

Это **второй из трёх адресов знания** (см. README шаблона, «Правило трёх адресов»).
Механизм: файл в `.claude/rules/` с полем `paths:` во фронтматтере подгружается только
тогда, когда агент открыл файл, попавший под этот шаблон. В сессии, которая таких файлов
не касается, он не стоит ни одного токена.

**Повод:** у класса файлов появилась конвенция, которая (а) перестала помещаться в корневой
`CLAUDE.md` и (б) называется одним выражением-шаблоном путей. Пока конвенция помещается в
две строки — ей здесь рано: две строки в корневом файле дешевле нового механизма.

**Почему этого файла нет в шаблоне готовым.** Потому что готовым он был бы правилом,
написанным впрок, — против чего возражает `CLAUDE.md` этого же шаблона. Файл-правило с
плейсхолдерами вместо правил не учит ничему, чему не учит этот блок, а строка-указатель на
него в корневом `CLAUDE.md` стоила бы контекста в каждой сессии, указывая на пустое место.

Готовый файл — целиком, заменить `tests/**` и содержание на своё:

```markdown
---
paths:
  - "tests/**"
---

# Правила для тестов

Сюда попадает то, что верно ТОЛЬКО для тестов: изоляция от сети, фикстуры, что считается
флаки, чего в тестах делать нельзя.

- Тесты не ходят в интернет. Внешние вызовы перехватываются <чем>; новый тест, делающий
  такой вызов, обязан делать то же.
- Тест, который «иногда падает», чинится или удаляется, но не перезапускается.
```

**И одну строку — в `CLAUDE.md`**, в раздел «Где что лежит». Вместе с файлом, а не раньше него:

```markdown
- Правила, действующие только на тесты: `.claude/rules/tests.md` (шаблон `tests/**`).
```

Зачем указатель, если glob работает сам, — в README шаблона, там же: после `/compact`
корневой файл возвращается сам, а правило с `paths:` — только когда агент снова откроет
подходящий файл.

**Грабли шаблона путей.** Невалидный glob (скажем, неэкранированная `[`) не совпадает ни с
чем, и правило по этому шаблону молча не срабатывает — без ошибки и без предупреждения.
Документация Claude Code (`code.claude.com/docs/en/memory`, снято 2026-09-24) добавляет две
оговорки, обе стоит знать: остальные шаблоны того же правила продолжают работать, а до версии
2.1.207 один невалидный шаблон ронял инструмент `Read` на КАЖДОМ файле — то есть раньше
поломка была громкой, а теперь тихой. Проверять, что правило реально загрузилось, командой
`/context`, а не тем, что файл лежит на месте.

## Первая запись в `doc/adr/` — «Записывать архитектурные решения»

`doc/adr/` в шаблоне — папка с форматом (`0000-template.md`) и порогом, но БЕЗ записей.
Шаблон не может знать, что вы решили вести ADR: сам факт копирования шаблона таким решением
не является. Датированная запись со `Status: Accepted` от вашего имени, которую приняли не
вы, — то же самое правило впрок, против которого возражает `CLAUDE.md`.

**Повод:** первое решение, которое не уложилось в три строки `DECISIONS.md`. Тогда заводятся
сразу два файла: эта запись и та, из-за которой она понадобилась.

Готовый файл — `doc/adr/0001-zapisyvat-arhitekturnye-resheniya.md`, подставьте дату и своё
обоснование в Context:

```markdown
# 1. Записывать архитектурные решения

Date: YYYY-MM-DD

## Status

Accepted

## Context

`DECISIONS.md` ведётся с дня 0 и покрывает решения, которые укладываются в три строки
«почему». <Решение, которое в три строки не уложилось, и почему.> Это и есть сигнал.

## Decision

Мы будем вести решения с долгими последствиями как ADR — по одному файлу на решение, в
формате Michael Nygard, в `doc/adr/`. Короткие «почему» остаются в `DECISIONS.md`; порог
между ними — влезает ли запись в три строки.

## Consequences

Каждое такое решение стоит отдельного файла — заметная дисциплина, и часть решений её не
окупает; такие остаются в `DECISIONS.md`.

Взамен вопрос «почему так» получает адрес. Отменённое решение не редактируется: у него
меняется `Status` на `Superseded by ADR-NNNN`, а новое пишется отдельным файлом.
```

**И строку — в `CLAUDE.md`**, если её там ещё нет: `с последствиями надолго — doc/adr/`.

## Где что лежит (указатели, не содержание)

**Этот раздел уже есть в вашем `CLAUDE.md`** — он единственный из перечисленных здесь
заведён с первого дня, потому что файлы, на которые он указывает, шаблон ставит сразу: их
надо найти, а не дождаться повода. Это и есть третий адрес из «правила трёх адресов» (README).

Что с ним делать: дописывать строку, когда в проекте появляется новый адрес знания, и
следить, чтобы в него не переехало содержание. Как только строка перестала быть адресом
и стала объяснением — раздел перестал быть указателем.

## Потолок

Повод: файл перевалил за то, что вы готовы платить каждым запросом.

```markdown
## Потолок

- **Инструкции: <N> слов** в этом файле. Новое правило, пробивающее потолок, означает,
  что что-то другое сокращается или уезжает в свой адрес — а не дописывается сверху.
```

Такой файл растёт только добавлением, если его никто не сокращает. Добавляя раздел,
спросите, какой существующий должен сжаться или уйти.
